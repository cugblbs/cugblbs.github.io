最近发现手里同时在推进的小项目比我想象的多。正好借这个机会，用 Build in Public 的方式把每个项目的现状、卡点和下一步计划都摊开写下来。

## 为什么要 Build in Public

一个人做项目最大的问题是：**没人看得见，自己又容易放弃**。把进度公开出来，相当于给自己签了一份"软合同"——下篇文章见的时候，总得推进点什么。

所以这篇是第一期，后面争取每周或每两周更新一次进度。

## 正在做的项目

### 1. 存钱目标打卡 iOS App

一个帮助用户"为某个目标存钱"的 SwiftUI App。核心思路是游戏化的存钱打卡：设定目标 → 每日打卡 → 攒够即达成。

- 状态：MVP 代码骨架已完成，页面流 `Welcome → CreateGoal → Home → CheckIn → Success` 齐全
- 已完成：SwiftUI 页面、`Goal / SavingRecord / CoverTheme` 数据模型、UserDefaults 本地持久化
- 卡点：还没有在 Xcode 里完整编译验证，Assets、AppIcon、启动图也还没补齐
- 下一步：跑通编译 → 补空状态/达成态细节 → 准备上架素材（发布检查清单已经备好了）

### 2. iOS 分贝测量 App

一个实时噪音测量工具，也是我练手 SwiftUI + SwiftData 的项目。最近刚在真机上跑通了第一次调试，算是里程碑。

- 状态：真机接入前最后一批问题已修复
- 已完成：麦克风权限、实时分贝测量、当前/平均/峰值/最低值展示、测量结果自动存 SwiftData、设置页校准偏移联动
- 工程化：三个页面统一到同一套设计系统，公共背景/卡片组件、动效 token 都抽出来了
- 卡点：还没有系统性的真机验证和视觉 review
- 下一步：完整走一遍真机测量流程 → 修交互细节 → 决定是否上架

### 3. 本地账单记录微信小程序

极简的本地账单记录小程序，只有"账单列表 + 记账表单"两个页面，数据全部存在本地，不折腾后端。

- 状态：功能闭环已完成，最近一轮主要在打磨视觉和文案
- 已完成：账单增删改查、自定义导航栏、移动端 UI 适配和复制校准
- 卡点：缺少数据统计维度（分类占比、月度趋势），也还没想清楚要不要做导出
- 下一步：先加月度汇总视图，再补分类标签

### 4. 办公技巧内容流水线（AI 辅助写作）

一个偏"内容工程"的项目：用一套固定的 prompts + 模板 + 排期表，每周稳定产出 PDF / 办公效率类的公众号文章，配图用 AI 生成的 SVG。

- 状态：已发布多篇，包括 WPS 快捷键、PDF 转 Word 排版、文件管理三篇
- 已完成：选题-写作-配图-发布的完整流程沉淀成了模板和排期表
- 卡点：选题质量参差不齐，排期表有，但没有严格的发布复盘
- 下一步：补上阅读数据复盘，反向校准选题池

## 复盘与下一步

几个整体观察：

1. **同时在推的项目有点多**（3 个项目 + 1 条内容线），注意力被稀释了。下个月想收敛到"2 个主项目 + 1 条内容线"的节奏。
2. **iOS 两个 App 都卡在"离上架差最后一公里"**：代码侧收口了，但真机验证、资产补齐、商店素材这些脏活还没干。这是接下来最该补的。
3. **内容流水线验证了一个假设**：靠固定流程 + AI 辅助，个人也能稳定产出内容。下一步是让数据反哺选题。
